# Host read deadline and claim unwinding

Bugfix L3. Actual host ignored documented DOM setup deadlines; outer tool reset killed finally cleanup and stranded claims. A fresh own X page reproduced it; native Chrome AX and URL inventory remained responsive, while DOM and screenshot did not. Not proof of429/OOM, or all computer UI freezing.

AC1 a stalled single read returns a local named timeout independent of the host promise. AC2 a late read result/rejection never resumes the caller or activates anything. AC3 the binding queues no further reads until that pending primitive settles; a different legitimate tab/binding remains independent. AC4 pre-submit timeout unwinds existing claim with zero activation; post-submit state stays original unknown/intent for verification. AC5 never race/cancel click, navigation, fill or submission; no promise that an activated write was cancelled. AC6 ordinary fast reads add no external calls. AC7 exercise the real ignored-timeout boundary without diagnostic posts and verify the original role adopts the artifact.

Design review: bound observation, screenshot and the exact navigation read primitives where incidents occurred. No global proxy or broad operation race. Each run accepts only an internal read primitive, not an async workflow that might later navigate/write. Local timeout rejects its caller; existing finally/CAS cleanup owns claims. The late read can still exist externally; results are discarded and a latch stops another read on that binding. This does not fix the external browser transport or make all browser methods cancellable.
