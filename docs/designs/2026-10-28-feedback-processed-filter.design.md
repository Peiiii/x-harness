# Skip previously handled reply detail reads

The incoming reader supplies previously resolved reply IDs, but feedback currently opens each visible reply before the caller can filter it. In the observed slow browser channel a single feedback batch took 905 seconds. This change adds an optional list of already resolved IDs to the existing feedback API and skips only their detail navigation after the bounded window has been selected. It preserves the original window, ordering, root checks, unconfirmed results and defaults when the option is absent. The consumer may supply only IDs whose existing contract already excludes them; unresolved selected items remain eligible.

Acceptance: synthetic tests show skipped IDs cause no detail navigation, other IDs retain exact parent verification, and absent or invalid filters cannot silently hide replies. Typecheck and affected tests pass. Real adoption requires verified build, matching consumer, and separate end-to-end timing; this change alone does not clear existing claims or establish browser transport recovery.

The observed batch contained 13 replies absent from the processed list, so filtering alone would not improve that batch. Add an explicit candidate-only mode: the same bounded root thread returns observed candidate IDs and URLs as unconfirmed candidates, never as verified replies or parent relationships. The consumer queues those candidates and sends up to five through the existing exact conversation reader before any writing decision. Retain unprocessed remainder in existing coverage; reject bad card URLs/identities and never declare a missing root or alert a successful empty result. The original default retains its existing detail verification. Validate both modes, filtering, missing/alert behavior and the consumer's preservation and later verification of candidates before live adoption.
