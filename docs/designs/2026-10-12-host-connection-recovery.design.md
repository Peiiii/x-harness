# Host connection recovery

The desktop host can fail before an owned tab is bound, outside the business API's existing error boundary. Its exact request-header initialization error asks callers to retry but does not expose the underlying HTTP cause. Native search is not a supported substitute.

Keep the single root export and inert synchronous binding. Add an asynchronous overload accepting a supported host connection port: a read-only check and a one-shot owned-tab open. Only the exact retry instruction allows one additional read-only check. Never retry open, binding, reads, submissions, policy refusals or unknown errors. Retain a returned tab even when binding or proof persistence fails. Do not modify vendor policy or authenticated transport. No check belongs on every subsequent operation.

The first failure must be recorded before retry; recovered and terminal outcomes preserve attempt stages, durations and original errors locally. Public receipts contain stable classification and proof references, never full host output. Hidden HTTP cause is explicitly unknown. Proof persistence failure stops rather than silently discarding the evidence. Construction and the optional connection check never change the business ledger.

Acceptance: first success invokes check/open once; transient policy failure checks twice and opens once; persistent failure checks twice and opens zero times; refusal/unknown checks once; creation failure never reopens; proof failure stops recovery; binding failure retains the returned tab; original synchronous factory/root export remains compatible. Validate declarations, runtime tests, Skill budgets and the installed package through a real supported host connection plus root read. Live healthy-path evidence does not establish live failure recovery; use synthetic fault injection for retry and denial boundaries.

Design review: passed. The two-stage connection port is required because blindly retrying tab creation after an opaque error could duplicate tabs. This isolates the retry to a documented read-only host operation. No shared state owner or workflow engine is added.

Implementation review: passed. The synchronous factory is extracted unchanged into the original binding dependency path; the asynchronous overload introduces no dependency cycle or extra root export. The exact initialization error is the sole retry condition; first-failure evidence persistence is required before a second check. A returned tab survives bind/proof failure, and no business callback is replayed. Original host output never enters public receipts. Source check passed: 182 tests including 11 connection cases, TypeScript/CLI/public declaration contracts, formatting, maintainability and Skill budgets. First-connection Skill load is 3,491 Unicode code points, separate from routine read/recovery loading; these are not billed tokens. Installed real-host acceptance follows release.
