# Read observed post images through the root harness

Bugfix / L3 capability gap. Existing readPost yields image URLs but no reviewable pixels; consumers cannot complete media review through the root. Add readPostMedia({target,maxImages?}) on the existing XGrowthHarness, composed with its original fresh readPost. Native or hosts without pageAssets return needsCapability. No screenshots, direct asset navigation, arbitrary URL fetches, writes or approval inference.

Owner: a PostMedia reader injected by binding, using the documented CUA pageAssets list/bundle ports. CuaTab exposes only the optional existing capability collection. The original store owns proofs; downloaded files stay in the host's temporary artifact directory. Source text and qualification remain original readPost/consumer responsibilities.

The root must first obtain observed, fresh, complete matching post evidence. Accept only explicit pbs.twimg.com/media HTTPS images from that post's images, not quote cards, avatars, other inventory assets or caller-supplied URLs. Inventory page must match the current exact target route; bundle only exact discovered image URLs and original inventory IDs. Bound 1–4 images, no silent truncation: larger sources/partial inventory or bundle failures remain incomplete. Enforce the original executor's explicit window (including expiry) or legacy daytime before acquisition and again before bundling; crossing midnight never exports. Preserve failures and partial paths without treating them as review approval.

Golden path: original observed source -> root fresh post -> exact page asset inventory -> selected original images exported -> returned local paths -> consumer views pixels -> full semantic review -> original comment queue/verification. Unit/assembled tests cover missing capability, wrong/partial source, unrelated inventory images, route drift, limit/partial export, no images, errors and executor/midnight boundaries. Type/build/contracts/maintainability and live original-root export plus local image inspection are required. Throughput remains measured separately; no speed guarantee.

Design review: passed. Reuses the supported pageAssets inventory/bundle API and original read/identity/window owners, without introducing a transport, second ledger, screenshot substitute or policy-specific implementation. plan: not-required; one bounded batch. Live acquisition cannot be replaced with mocks.

Live export/image review remains a consumer acceptance step.
